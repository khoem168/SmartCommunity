# Section 05 — Project Outcomes and Challenges

Presentation-ready content for the **Smart Community Skill & Career Development Platform**.

## Verified project scope

The following presentation content is based on features that exist in the codebase:

- React 19 + Vite user interface with protected and public routes.
- Node.js + Express REST API with MySQL/MariaDB data storage.
- JWT authentication, bcrypt password hashing, rate limiting, and role-based access.
- User profiles, courses, mentorship, skill exchange, career roadmaps, internships, community forum, chat, notifications, analytics, and administration.
- Socket.IO real-time messaging and notifications.
- Jitsi online learning and mentorship meetings.
- Bakong KHQR premium-course payment and server-side payment verification.
- Khmer and English interfaces with responsive layouts.
- Vercel frontend, Render backend, and Aiven MySQL production architecture.

## Slide 18 — Anticipated Challenges

### Anticipated Challenges

1. **Module integration**  
   Keeping authentication, courses, mentorship, internships, chat, and administration connected through consistent data flows.

2. **Security and permissions**  
   Protecting personal data, uploaded files, payment access, and role-specific actions for students, mentors, recruiters, and administrators.

3. **Scalable database design**  
   Maintaining relationships and data consistency across users, skills, courses, payments, applications, messages, and progress records.

4. **Real-time and third-party services**  
   Handling Socket.IO connections and integrating Jitsi, Bakong KHQR, Cloudinary, Firebase, and hosted services reliably.

5. **Responsive bilingual UX**  
   Keeping Khmer and English text clear and visually consistent across phones, tablets, laptops, and desktop screens.

6. **Testing, deployment, and time management**  
   Debugging complex user flows, managing environment variables, coordinating team changes, and delivering within the academic schedule.

## Recommended visual style

- Use a white or very light blue background with navy headings.
- Use one primary blue and one teal accent; avoid several unrelated colors.
- Use one simple line icon per card: layers, shield, users, database, radio, or cloud.
- Keep each card to one heading and no more than two short lines.
- Reveal the title first, then cards one at a time with a subtle 0.3-second fade-up.
- Avoid bouncing, spinning, or strong 3D animations during an academic presentation.
- Use at least 30–36 pt for slide titles, 20–24 pt for card titles, and 16–20 pt for body text.
- Keep equal card heights, equal icon sizes, and consistent spacing.
- Use bold only for keywords; do not bold entire paragraphs.

## Likely teacher questions and clear answers

### 1. What makes this different from a normal learning website?

It combines courses with peer skill exchange, verified mentorship, live sessions, internships, career roadmaps, community discussion, and real-time communication in one platform.

### 2. How is user data protected?

Passwords are hashed with bcrypt, authenticated sessions use signed JWTs, protected APIs check user roles, and production secrets are stored in hosting environment variables rather than source code.

### 3. Why did the project use MySQL?

The platform contains strongly related data such as users, skills, courses, payments, applications, sessions, and messages. A relational database helps preserve those relationships and maintain consistency.

### 4. How does real-time communication work?

The backend uses Socket.IO. An authenticated user joins only authorized user and conversation rooms, allowing new messages, typing indicators, unread counts, and notifications to update immediately.

### 5. How does course payment work?

The backend generates a Bakong KHQR code using a server-controlled course price. Full course access is granted only after the backend verifies the transaction and creates the enrollment record.

### 6. What happens if an external service is unavailable?

The interface shows a clear loading or error state and provides a retry path. Optional services use configuration checks and local fallbacks where the feature safely allows them.

### 7. What would be improved next?

The next priorities are broader user testing, automated browser tests, stronger monitoring, performance optimization, production email and push-notification configuration, and continued security review.
